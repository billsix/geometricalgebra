## BLUF

Before gacalc can hold OpenGL code it has to be able to run that code. Done means:
- `pyproject.toml` has a `gl` extra;
- gacalc's image installs the GL system libraries and the pinned `gl` packages into `/venv`;
- `make shell` can open a GLFW window on X11 and on Wayland.

## Context

- gacalc's runtime dependencies are `["numpy", "sympy"]` (`pyproject.toml`, the `dependencies`
  line). The extras pattern to copy is the `notebooks` group just below it.
- gacalc's Makefile already defines `X_FLAGS_FOR_CONTAINER` and `WAYLAND_FLAGS_FOR_CONTAINER`. Check
  which targets use them. Mesa is installed only under `USE_SPYDER`
  (`entrypoint/02-install-spyder.sh`), and `USE_SPYDER` stays 0 everywhere.
- mvp's working set, from github.com/billsix/modelviewprojection:
  - `requirements.txt` pins `glfw==2.11.0`, `imgui-bundle[glfw]==1.93.0`, `PyOpenGL==3.1.10`,
    `PyOpenGL-accelerate==3.1.10` and `Pillow==13.0.0`.
  - `entrypoint/01-install-base.sh` installs `glfw` (plus `python3-glfw`).
  - `entrypoint/03-install-xwindows.sh` installs `mesa-dri-drivers` and `mesa-libGLU-devel`.
- `gacalc.gl.labels` (step 3) shells out to `texExpToPng` (github.com/billsix/tex-expression-to-png)
  and turns itself off if that is absent, so it is optional here.
- Follow the Python-deps rule in the shared conventions: every package goes into `/venv` with uv, and
  the resolved set is locked in gacalc's `constraints.txt`, regenerated by its pin-update target.

## Plan

1. Add `gl = ["glfw", "PyOpenGL", "PyOpenGL-accelerate", "imgui-bundle[glfw]", "Pillow"]` to
   `[project.optional-dependencies]`. Leave it unpinned, like the other extras, since a library
   shouldn't force versions; the image pins through `constraints.txt`.
2. Add a `USE_GRAPHICS` group:
   - an `entrypoint/0N-install-graphics.sh` with the dnf packages (glfw, mesa-dri-drivers, and
     anything else a GLFW window needs);
   - a Dockerfile `ARG USE_GRAPHICS=0` declared just before its layer;
   - a Makefile `USE_GRAPHICS ?= $(if $(filter 1,$(MINIMAL_IMAGE)),0,1)`.
3. Install the `gl` extra's packages into `/venv` in the image, and regenerate `constraints.txt`.
4. Make sure `shell` and `shell-exec` carry the X11 and Wayland flags.
5. Verify:
   - (a) a nested `make image` builds;
   - (b) with the image built, `python -c "import glfw, OpenGL.GL, imgui_bundle"` succeeds in
     `make shell-exec`;
   - (c) on the host, a two-line GLFW window opens (only the maintainer can see a window). Headless
     alternative: run under Xvfb (`~/.claude/reference/nested-run-and-gates.md`, the headless
     recipe).
