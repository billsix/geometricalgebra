# CI guard: committed generated code must match the generator

**Created:** 2026-06-04 · **Completed:** 2026-06-06
**Superseded:** the `git diff --exit-code` guard over committed g*.py was superseded once g*.py became gitignored; determinism is now checked by `make check-generated` (see `tasks/reference/design-decisions.md`).

`g1.py`/`g2.py`/`g3.py` and `scalar.py` were generated by `tools/gen_specialized.py` and committed
(`tasks/archive/2026/06/06/codegen-checkin-strategy.md`). The standard safety net for committed
generated code is to re-run the generator and fail on any difference, so a hand edit to a generated
file, or a generator change without a regen, cannot drift silently.

## Why it was easy by then (2026-06-06)

1. **The generator formats its own output:** `main()` calls `ruff_format(written)`, so a fresh run is
   byte-identical to the committed files with no separate format step.
2. **It is deterministic:** two consecutive runs were byte-identical during the
   master ↔ abstractBaseClass merge. `term_grade_key` reads `term.free_symbols` (a set), but each
   term has exactly one `a_`/`b_` symbol, so the key does not depend on iteration order.

## Decisions

- **A `make check-generated` target**, not a pytest test or a CI-only step: the regen mutates the
  working tree and takes ~30 s (𝒢₃'s symbolic products dominate), wrong for the default fast
  `pytest`. The repo had no CI config, so the make target was the deliverable and the thing a future
  CI step would call. Rejected alternatives: a slow-marked pytest test regenerating into a temp dir;
  an in-process comparison without the ruff step (the committed files are stored formatted).
- **All algebras are regenerated**, 𝒢₃ included: `main()` writes them in one pass, so no exclusion
  from a fast path was needed.

## What changed

`make check-generated` runs `python tools/gen_specialized.py`, then `git diff --exit-code` over
`scalar.py` and `g1/g2/g3.py`, with an explanatory error message on drift. Documented in `CLAUDE.md`
(Dev workflow) and the README (Generating section).

## Verification

A clean tree exits 0 (which also confirmed the committed files were in sync); a simulated drift made
`git diff --exit-code` exit 1 and printed the error block.
