# Step 2: a `gl` extra, and a gacalc container that can open a GL window

**Done:** 2026-11-13. **Created:** 2026-11-13.
**Part of:** `tasks/archive/2026/11/13/move-mvp-gl-toolkit-to-gacalc.md`
**Next:** `tasks/archive/2026/11/13/move-mvp-gl-toolkit-to-gacalc-step-3-gl-toolkit.md`

## Outcome

- **`pyproject.toml`** has a `gl` extra: `glfw`, `PyOpenGL`, `imgui-bundle[glfw]` and `Pillow`,
  unpinned like the other extras. `make update-pins` and the Dockerfile's dependency layer both
  pass `--extra gl`.
- **`constraints.txt`** was regenerated with the extra. It gained exactly three pins: glfw 2.11.0,
  imgui-bundle 1.93.0 and pyopengl 3.1.10, the versions modelviewprojection uses. Pillow 13.0.0 was
  already pinned, and no other pin moved. It was regenerated by running `update-pins`' own
  `podman run` line against the existing image, which skipped the target's `: image` rebuild.
- **System libraries** come from a new group script, `entrypoint/07-install-gl.sh`: `glfw`,
  `mesa-libGL`, `mesa-libEGL` and `mesa-dri-drivers`. The Dockerfile runs it in its own layer just
  before the Python dependency layer, unconditionally.
- **The X11 and Wayland passthrough** was already on `shell` and `shell-exec` (`SHELL_RUN_FLAGS`
  carries `X_FLAGS_FOR_CONTAINER` and `WAYLAND_FLAGS_FOR_CONTAINER`), so the Makefile needed no
  change for it.
- **Docs:** a `CHANGELOG.md` `[Unreleased]` "Added" entry for the extra, and `CLAUDE.md`'s
  Packaging line.

## Decisions (the agent's, 2026-11-13; the plan had proposed otherwise)

- **No `USE_GRAPHICS` flag; the GL packages are always installed.** The plan proposed a
  MINIMAL_IMAGE-gated flag. But `make test` collects doctests from all of `src/`, so after step 3 it
  imports `gacalc.gl`, and the lean CI image (`MINIMAL_IMAGE=1`) must still pass that gate. That
  follows the convention that a flag a gate needs is not dropped by a lean image (the
  minimal-nested-images.md reference doc in github.com/billsix/runClaudeInContainer). The packages
  are small next to the image.
- **Their own late layer, not `01-install-base.sh`.** The base group's layer sits before the TeX,
  Jupyter, Lean and ePiX layers, so adding the packages there would have rebuilt all of those, on
  the maintainer's host as well as nested. A late layer kept every earlier layer cached: the
  nested build reused 21 of them from the host.
- **PyOpenGL-accelerate is left out of the extra.** modelviewprojection pins it, but it has no
  binary wheel for Python 3.15 (`uv pip install --only-binary :all:` failed on it alone), so
  building it would need a compiler, and gacalc's lean image has none. It is optional: it speeds
  up PyOpenGL's array marshalling and silences an INFO log line. The umbrella's decision 1 records
  this.

## Verification

- **Wheels:** in a throwaway venv on the sandbox's Python 3.15.2, `--only-binary :all:` installed
  glfw, PyOpenGL, imgui-bundle[glfw] and Pillow.
- **Image:** a nested `make image` exited 0. In the image, `import glfw, OpenGL.GL, imgui_bundle,
  PIL` works, and `rpm -q` finds all four system packages.
- **A real window:** Xvfb ran in the sandbox with its socket shared into the image, per the
  nested-run-and-gates.md reference doc in github.com/billsix/runClaudeInContainer, and every launch
  was wrapped in `timeout -s KILL`. A probe (glfw window, clear to green, `glReadPixels`) reported
  `GL_VERSION 4.6 (Compatibility Profile) Mesa 26.2.6` and read back `[0, 255, 0]`.
- **Bare host:** `07-install-gl.sh` run alone in a fresh `fedora:45` container exited 0 and
  installed all four packages.
- **Tests:** `make test`'s own `podman run` line against the new image gave 1,220 passed,
  2 skipped, 11 deselected, the same as step 1.
