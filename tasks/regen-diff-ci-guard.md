# CI guard: committed generated code must match the generator

Status: **not started** · proposed 2026-06-04 · needs a go/no-go

## Background

`src/geometricalgebra/g1.py`, `g2.py`, `g3.py` are generated by `tools/gen_specialized.py` and
**checked in** (the idiomatic Python choice — keeps ruff/ty/IDE/debugger working). The standard
safety net for checked-in generated code is a test that **re-runs the generator and asserts the
output is byte-identical to what's committed**, so the two can never silently drift (e.g. someone
edits a generated file by hand, or changes the generator but forgets to regenerate).

## Sketch

A pytest test (or a `make`/CI step) that:
1. runs `tools/gen_specialized.py` into a temp dir (or captures `generate_class`/`generate_constants`
   + `header` output in-process), and
2. compares against the committed `g*.py` (after the same `ruff format` the repo applies), failing
   on any diff. The classic shell form is "regenerate, then `git diff --exit-code -- src/...g*.py`".

## Caveat — generation is slow

The generator runs `Gn`'s **symbolic** geometric/inner/outer products to derive the closed forms:
sub-second for 𝒢₁/𝒢₂ but **tens of seconds for 𝒢₃** (minutes for higher). A full-regen test would
make the suite noticeably slower. Options:
- only regen-diff `g1`/`g2` in the fast test, and gate `g3` behind a slow/`-m slow` marker or CI-only;
- or compare in-process without the `ruff format` step (faster, but then the committed file must be
  stored pre-format, which it isn't).
